# 固件结构分析（初稿）

> 脚本：`scripts/parse_mcs.py`  
> 输入：`assets/firmware/20230825_s2056.mcs`

## 解析结果（✅ 脚本实测）

| 项 | 值 | 证据等级 |
|----|----|----------|
| 格式 | Intel HEX / MCS（CRLF） | ✅ |
| 镜像跨度 | 6,692,588 bytes（~6.38 MB） | ✅ |
| 非 0xFF 数据 | 6,673,113 bytes | ✅ |
| Boot header `000000BB11220044` | offset 32，出现 1 次 | ✅ |
| Sync `AA995566` | offset 48，出现 1 次 | ✅ |
| 明文 Xilinx/USER/Date 字符串 | 未发现 | 🔶 |
| IDCODE XC7K160T (`0x03631093`) | **未找到** | ❓ |
| 其它 Kintex-7 IDCODE | 未找到 | ❓ |
| 镜像数量（boot header 计数） | 疑似单镜像 | 🔶 |

## 初步结论

1. **这是合法的 Xilinx 7 系 SPI 配置镜像结构**（有标准 boot header + sync）。✅  
2. **未能在二进制中直接扫到 XC7K160T IDCODE**。可能原因：  
   - 位流经压缩/加密后 IDCODE 不以明文出现  
   - 字节序/包格式需按 packet 解析而非裸搜  
   - 目标器件不是 XC7K160T（与照片冲突 → 待 Vivado/JTAG 确认）  
3. **无明文字符串** 提高“压缩或加密”概率，但**不能**仅凭此断定 AES。❓  
4. Flash 芯片约 16 MB，固件 ~6.4 MB，空间足够，且目前迹象偏向**单用户镜像**。🔶
