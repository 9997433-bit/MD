# 位流网络常量搜索

> 目的：在 `20230825_s2056.mcs` 展开镜像中搜索是否存在**硬编码的网络常量**
> （IPv4 地址 / MAC OUI / 常见 UDP·TCP 端口），以判断该 FPGA 位流内部是否内置
> 网络协议栈配置（如以太网软核的 IP/MAC 默认值、端口表）。
> 脚本：`scripts/search_net_constants.py`
> 关联：`固件结构分析.md`、`位流特征与软核线索.md`、`04_comms/以太网通路研究.md`

## 结论（先读）

| 结论 | 等级 |
|------|------|
| **未发现可信的硬编码网络常量**（IP/MAC/端口均为统计巧合，非对齐配置表） | ✅ |
| 镜像 88.94% 为 `0x00`、整体熵仅 **1.136 bit/byte** → 属稀疏 FPGA 配置帧数据 | ✅ |
| “命中”的 IP/端口全部来自滑窗扫描零填充区/帧位模式，**无重复、无对齐、无成表** | ✅ |
| 与既有判定一致：这是**原始 Kintex-7 配置位流**，非带网络栈的 CPU 固件镜像 | ✅ |
| 若存在网络配置，更可能在独立 Flash/EEPROM 区或运行时下发，而非位流内 | 🟡 推断 |

## 方法

对展开后的线性镜像（`assets/firmware/20230825_s2056.bin`，可由 `.mcs` 再生）做三类搜索，
大端与小端均覆盖：

1. **IPv4**：4 字节滑窗，按大/小端解读，只保留“有意义”网段
   （私网 10/8、172.16/12、192.168/16，环回 127/8，链路本地 169.254/16，
   组播 224–239，CGNAT 100.64/10），并跳过四字节全同（如 `00000000`/`FFFFFFFF`）。
2. **MAC OUI**：对一张厂商 OUI 表（含 Xilinx `00:0a:35`、板载/常见网络芯片厂商）
   做 3 字节前缀匹配，命中处取后续 6 字节还原完整 MAC。
3. **端口**：对常见 UDP/TCP 端口（DHCP、DNS、NTP、SNMP、TFTP、PTP、Modbus、
   HTTP(S)、SSDP、mDNS、`0x1234` 占位等）按大/小端 2 字节统计出现次数并抽样偏移。

每条命中附带前后字节上下文（hex），便于人工研判是“真常量”还是“零区/帧位巧合”。

## 镜像总体特征

| 指标 | 值 |
|------|-----|
| 长度 | 6,692,588 B（6.383 MiB） |
| 整体熵 | 1.1360 bit/byte（极低 → 大量重复/零） |
| `0x00` 占比 | 88.94% |
| `0xFF` 占比 | 0.29% |

低熵、近 89% 全零，说明这是**未加密的 Xilinx 7 系列配置位流**（大量配置帧为空/默认），
而非包含代码段、数据段与配置表的 CPU 固件。这直接决定了下述“命中”的性质。

## 结果与研判

### IPv4：34,100 处“命中”——全部为巧合

| 网段 | 命中数 |
|------|-------:|
| 私网 10/8 | 23,668 |
| 组播 224–239 | 8,718 |
| 环回 127/8 | 1,494 |
| CGNAT 100.64/10 | 183 |
| 私网 172.16/12 | 20 |
| 私网 192.168/16 | 13 |
| 链路本地 169.254/16 | 4 |

判为巧合的证据：

- **来源可解释**：`10/8` 海量命中源于窗口首字节 `0x0a`——它既是零区边界字节，
  也是配置帧中的高频位模式；`224–239 组播` 源于 `0xE0–0xEF` 高位字节同理。
- **无对齐**：命中偏移多为奇数、彼此重叠（同一段字节被大/小端各解读一次），
  不落在 4 字节边界，不符合真实配置结构。
- **无重复成表**：真实设备的默认 IP 会作为一个稳定 32 位常量在固定位置出现（常伴掩码、
  网关）。这里**没有任何一个具体 IP 在多处一致复现**。例如用户示例的 `c0a80001`
  (192.168.0.1) 未出现；出现的 `192.168.0.0`(`0000a8c0`) 仅是 `a8c0` 落在零区内。
- 逐条抽查 `192.168/`、`172.16/`、`169.254/` 稀有段（见脚本 `--json` 输出），
  上下文均为随机帧字节，无掩码/网关/端口的相邻结构。

### MAC OUI：16 处“命中”——均落在零区，无效

命中的 OUI（如 Xilinx `00:0a:35`、Intel `00:0e:0c`、Dell `00:1c:23` 等）后 3 字节
几乎全为 `00 00 00`，即形如 `…00 00 0a 35 00 00 00…`——是**零填充区里恰好出现 OUI 三字节**
的假阳性，而非真实网卡地址（真实 MAC 的低 24 位序列号极少全零）。无一处构成可信 MAC。

| 偏移 | 匹配 | 上下文 | 研判 |
|------|------|--------|------|
| 0x23E279 | 00:0a:35:00:00:00 (Xilinx) | `…000a350000…` | 零区巧合 |
| 0x290788 | 00:50:c2:00:02:40 | `…0050c2000240…` | 零区巧合 |
| 0x2986D8 附近 | 00:0e:0c… (Intel) | 帧位区 | 巧合 |

### 端口：高频值均由零区主导，无有效信号

按出现次数看，`80(HTTP)`、`514(Syslog)`、`520(RIP)`、`68(DHCP client)`、
`49152` 等计数最高（数千次），但它们的字节形态（如 `0x0050`、`0x0202`、`0x0208`、
`0x0044`、`0xC000`）在近 89% 全零、且富含 `0x00/0x02/0x08/0x20/0x40/0x80` 的位流中
本就极易出现，属噪声。反而**计数极低者**（如大端 `319 PTP` 1 次、`1900 SSDP` 1 次）
数量太少、上下文无关联，同样不足以判定为真实端口配置。**无任何端口出现在与 IP/MAC
相邻的、可识别的网络配置块中**。

## 总体解读

三类搜索一致指向**否定结论**：位流内不存在硬编码网络常量。这与固件结构分析的既有判定
自洽——`20230825_s2056` 是一份**未加密的 Kintex‑7（XC7K160T）原始配置位流**，
不是运行网络协议栈的处理器固件，因此不应期望其中含 IP/MAC/端口配置表。

对“该设备是否有以太网/网络配置”的问题，应转向：

- 板上是否另有 **配置 Flash/EEPROM 区**（独立于 FPGA 位流）存放 MAC/IP；
- 网络参数是否由**上位机运行时下发**（见 `04_comms/以太网通路研究.md`、`USB_FT600Q.md`）；
- 若确有以太网软核（如 TEMAC/1G/2.5G MAC），其 MAC/IP 通常来自**外部寄存器写入**，
  而非烘焙进位流。

## 复现

```bash
    zero0000-research/assets/firmware/20230825_s2056.mcs
```
