# 位流特征与软核线索（L2 深化）

> 对象：`assets/firmware/20230825_s2056.mcs` → HEX 展开镜像 `20230825_s2056.bin`（6,692,588 B）
> 脚本：`scripts/analyze_bitstream.py`（本次新增，逐包/逐帧解析）、`scripts/analyze_mcs.py`、`scripts/parse_mcs.py`
> 证据等级：✅ 确认（位流字段/解析可直接支撑）/ 🔶 推断（间接、需交叉验证）/ ❓ 待证（无位流证据或需实物）
> 复现：`python3 scripts/analyze_bitstream.py assets/firmware/20230825_s2056.bin`

---

## 0. 一句话结论

这是一份 **完整、未加密、单镜像的 Xilinx 7 系列（XC7K160T）Master-SPI 配置位流**；包结构 100% 干净可解析。**位流中不含任何软核/外设明文符号**（属综合位流的正常现象，不能据此否定功能）。逐帧分析显示 **约 53% 配置帧非零（高逻辑占用）**，而 **块 RAM 内容区几乎为空**——间接说明板上大概率 **不存在以 BRAM 承载程序的软核 CPU（PicoBlaze/大 MicroBlaze）**，功能以定制数据通路逻辑为主。🔶

## 1. 位流身份与完整性 ✅

| 项 | 值 | 说明 | 等级 |
|----|----|------|------|
| 总线宽度/Boot 头 | `000000BB 11220044` @0x20 | 7 系列标准 bus-width 探测 + boot 序列 | ✅ |
| 同步字 SYNC | `AA995566` @0x30，全镜像仅 1 次 | 单一比特流 | ✅ |
| 器件 IDCODE | **`0x0364C093`** | 程序化解出 = **XC7K160T** | ✅ |
| 加密位 CTL0 | `0x00000501`，DEC(bit6)=0 | **未 AES 加密** | ✅ |
| Multiboot WBSTAR | `0x00000000` | **单镜像，无 golden/multiboot** | ✅ |
| 同步后 2 MiB 熵 | **1.12 bit/byte** | 明文未压缩配置数据（远离加密的≈8） | ✅ |
| 包解析结果 | 543 Type-1 + 1 Type-2 + 516 NOP，**解析异常 0** | 结构完全合法、无残缺 | ✅ |

> 注：`analyze_mcs.py` 早期库把 K160T 的 IDCODE 记为 `0x03631093` 有误；本次以“写 IDCODE 寄存器（reg 12）单字”的方式直接解码，确认为 `0x0364C093`，与 `固件结构分析.md` 修订版一致。

### 1.1 配置命令序列（CMD 寄存器写入流）✅

```
BSPI_READ → NULL → RCRC → SWITCH → WCFG → GRESTORE → DGHIGH/LFRM → START → DESYNC
```

这是 7 系列 **Master-SPI 全量配置** 的教科书流程。其中 **`BSPI_READ` 命令 + 对 BSPI 寄存器（reg 31）的单字写入** 明确表示位流以 **主 SPI（x1/x4）从 Flash 自举**。

**交叉印证 L3**：这把 L3《系统架构》中“FL128 为主 SPI 配置引导”的判断由 🔶 提升为 **✅（就配置引导模式而言）**——位流本身要求 Master-SPI 主控，与板载 FL128（S25FL128）SPI Flash 完全吻合。（模式引脚 M[2:0] 的物理连接仍需照片核对，故“上电确定走 SPI”整体保持 🔶。）

## 2. 配置包类型统计 ✅

| 寄存器 | 写次数 | 写入字数 | 含义 |
|--------|-------:|---------:|------|
| **FDRI**（帧数据写入） | 1×Type-2 | **1,672,560** | 主体配置帧流 |
| CMD | 9 | 9 | 见 §1.1 命令序列 |
| MASK | 3 | 3 | CTL0/CTL1 写保护掩码 |
| CTL0 | 2 | 2 | `0x00000501`（未加密） |
| FAR | 2 | 2 | 起始 `0x00000000` + 收尾 `0x03BE0000` |
| CRC | 2 | 2 | `0xA8FC5FE1` / `0xE3AD7EA5`（含最终 CRC 校验） |
| IDCODE / COR0 / COR1 / CTL1 / WBSTAR / TIMER / BSPI / reg19 | 各 1 | 各 1 | 标准头部寄存器初始化 |

- 操作码分布：**WRITE ×28、NOP ×516**，无 READ（回读）包——纯配置写入，符合出厂烧录镜像。
- COR0 = `0x02003FE5`（配置选项寄存器，含配置速率分频等），COR1 = 0，CTL1 = 0：均为常规值。
- reg19（0x13）单字写 = 7 系列位流头部的未公开保留寄存器初始化，属正常。

## 3. 帧结构与 BRAM 粗估 🔶

### 3.1 帧总量（= 器件规模，非利用率）✅

- FDRI 单段写入 **1,672,560 字 = 6,690,240 B**；7 系列每帧 101 字 ⇒ **16,560 帧**。
- 16,560 × 101 × 32 = **53,521,920 bit**，正好等于 **XC7K160T 整器件配置阵列**。
- 结论：**这是一份完整器件位流**。⚠️ 关键认知——**位流永远写满全器件所有帧（未用区域填 0）**，故“帧总数”只反映器件大小、**不等于设计利用率**。✅

### 3.2 逐帧非零分布（利用率与 BRAM 初始化的经验证据）🔶

对 16,560 帧逐帧判定“全零 / 非零”：

| 指标 | 数值 |
|------|------|
| 全零帧 | 7,730（46.7%） |
| **非零帧** | **8,830（53.3%）** |

按 FAR 递增顺序分 10 段的非零密度：

| 段 | 帧区间 | 非零率 | 形态 |
|----|--------|-------:|------|
| 0 | 0–1656 | 81.4% | 逻辑密集 |
| 1 | 1656–3312 | 74.5% | 逻辑密集 |
| 2 | 3312–4968 | 18.8% | 稀疏（IO/时钟列?） |
| 3 | 4968–6624 | 81.8% | 逻辑密集 |
| 4 | 6624–8280 | 73.4% | 逻辑密集 |
| 5 | 8280–9936 | 85.4% | 逻辑密集 |
| 6 | 9936–11592 | 72.7% | 逻辑密集 |
| 7 | 11592–13248 | 43.1% | 中等 |
| 8 | 13248–14904 | **0.0%** | 近乎全零 |
| 9 | 14904–16560 | **2.2%** | 近乎全零 |

**解读**：
- **非零帧 ≈ 53%** ⇒ 设计对 K160T 逻辑资源占用相当可观，属 **中高占用**（该值为“被触碰的配置区面积”，是逻辑利用率的**上界**，因为即便轻用的列也含非零布线帧）。🔶
- 在 7 系列 FAR 编码中，**块类型（bit[25:23]）是最高位段**，故 FDRI 线性流里 **块类型 1（BRAM 内容帧）位于高 FAR 尾部**。观测到 **尾部两段（帧 13248 起）几乎全零** ⇒ **初始化的 BRAM ROM 内容极少**。🔶
- 推论：板上 BRAM 更可能被当作 **上电清零即用的数据缓冲/FIFO（无需初值）**，而非承载固件程序的 **ROM**。🔶

> 局限：本镜像用 **单次 FDRI + 内部 FAR 自增** 写入全阵列，未把 BRAM 段拆成独立 blk=1 的 FDRI，故“逻辑帧 vs BRAM 帧”的**精确边界**需要器件帧地址映射（Vivado / bitstream frame map）才能定死。上文按“尾部区≈BRAM 内容”做的是**粗估**（❓ 精确计数）。

## 4. 软核 / 外设明文特征扫描（核心：多为阴性）

### 4.1 明文字符串搜索——全部未命中 ✅（阴性结论）

对全镜像做字节级检索，以下关键字 **命中次数均为 0**：

`MicroBlaze / microblaze / PicoBlaze / kcpsm / KCPSM / AXI / axi_ / Ethernet / TEMAC / tri_mode / GMII / RGMII / MDIO / FTDI / FT600 / FT601 / FT245 / UART / I2C / SPI / MIG / DDR3 / FIFO / Xilinx / Vivado / UserID / ChipScope / ILA / JTAG / PCIe / aurora / S25FL / 2023 / s2056`

广谱可打印串（≥6 字符）虽有 1,003 条，但经“含≥5 字母且低符号比”过滤后 **无一条是有意义词汇**（全是 `ZZffUU33` 类位流字节噪声）。

**重要判读**：综合后的配置位流 **本就不含网表符号/信号名**，`.mcs` 又剥离了 `.bit` 的 ASCII 头部。因此——
> **字符串阴性 = “位流里没有符号”，绝不等于“板上没有以太网/USB/软核功能”。** 该维度对功能判定**天然不可用**，只能作阴性背景。

### 4.2 由结构反推的软核/外设线索（间接）

| 目标 | 位流中可见性 | 本次证据 | 判读 | 等级 |
|------|--------------|----------|------|------|
| **MicroBlaze**（大核，程序驻 BRAM/LMB） | 需初始化 BRAM 内容 | BRAM 内容区近乎全零（§3.2） | **不太可能存在“BRAM 承载固件”的 MicroBlaze** | 🔶 |
| **MicroBlaze**（小核，程序从 SPI/DDR3 加载） | 仅需极小 bootloop BRAM | 无法证伪 | **不能排除** | ❓ |
| **PicoBlaze** | 程序恒驻单块已初始化 BRAM | 未见成规模 BRAM 初值 | **倾向不存在** | 🔶 |
| **AXI 互连** | 纯 fabric，永不出现在位流 | —— | 无法从位流判定 | ❓ |
| **以太网 MAC** | K7 **无硬核 MAC**，RGMII→RTL8211F 必为软逻辑（自研 MAC 或 TEMAC/AXI-Ethernet） | 53% 高逻辑占用与之相容 | 若启用则为软核逻辑；位流不可单独证明 | 🔶(硬件)/❓(位流) |
| **FT600/FTDI USB3** | 纯 fabric FIFO 逻辑，无签名 | —— | 器件确实在板（L1），位流无痕 | ✅(器件)/❓(位流) |
| **MIG/DDR3 控制器** | fabric 逻辑，无明文 | 高逻辑占用相容 | 大概率存在（板有 DDR3） | 🔶 |

**小结 🔶**：位流正面证据支持“**一个中高占用的定制数据通路设计**”（DSP 采集链 + 可能的 MIG + 软 MAC + USB FIFO），**未见嵌入式软核 CPU 的正面迹象**；PicoBlaze 与“BRAM 驻留程序的 MicroBlaze”可较有把握地排除，SPI/DDR 启动的小 MicroBlaze 仍待实物证伪。
