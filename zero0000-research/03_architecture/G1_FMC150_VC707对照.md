## 2. 时钟 / 插值（修正本板先验）

作者在 `fmc150_dac_config_pkg.vhd` 中写明（**硬件回读**）：

- CDCE 使能输出分频均为 Table-8 **÷2** → 各输出（含 DACCLK）= **245.76 MHz**（VCXO 491.52÷2）  
- 若仍用 **4x** 插值，会 FIFO 碰撞；故 CONFIG1 用 **2x（FIR0）** → Fdata = 245.76/2 = **122.88 MS/s**  
- 原计划「DACCLK=491.52 + 4x」在 **未确认哪一路 CDCE 输出接 DACCLK** 前被放弃  

| 计划 | ADC | DACCLK | 插值 | 数据率 | 来源 |
|------|-----|--------|------|--------|------|
| **B（Conserviss 实测）** | 245.76 | **245.76** | **2x** | 122.88 | 本仓 VHDL + 硬件笔记 |
| A（旧 FMC150/E2E 口头惯例） | 245.76 | 491.52 | 2x | 245.76 | 早期先验 |
| TSW4200 | 245.76（ADC） | （DAC 另配） | — | — | SLWU071 |

**对本板 P1.3**：候选族仍为 122.88 / 245.76 / 491.52；**不得再默认「DACCLK 必为 491.52」**。G2 测 C3/C6 后用 `DACCLK/DATACLK` 定插值。  
`g2_mode_infer.py` H8 已改为识别计划 A/B。

## 3. SPI 初值表（抓包对照 · 新靶标）

### 3.1 ADC（`fmc150_adc_config_pkg.vhd`）

| 字 | 含义 |
|----|------|
| `0x4180` | Reg 0x41：DDR LVDS |
| `0x5004` | Reg 0x50：two’s complement（DATA_FORMAT=10） |

### 3.2 DAC（`C_DAC_PRE_SYNC_CONFIG` 摘录）

| 字 | 含义 |
|----|------|
| `0x0070` | CONFIG0：FIFO on |
| `0x0121` | CONFIG1：**FIR0=2x** + two’s complement（**非**旧合成样例 `0x11`） |
| … | 另有 CONFIG2–30 复位清场 + 4-wire SDO 等 |

### 3.3 CDCE（`C_CDCE_INTERNAL_245M76`，源自 `cdce72010_init_int_491_52MHz.coe`）

完整 13 字（含地址半字节）：

`683C0350, 68000021, 83800002, 68000003, E9800004, 68000005, 68000006, 83800017, 68000098, 68050CC9, 05FC270A, 0000040B, 0000180C`

与旧 TI E2E「internal」列差异（抓包时勿只认旧值）：

| Reg | 旧 E2E data28 | Conserviss data28 |
|-----|---------------|-------------------|
| 0 | `683C034` | **`683C035`** |
| A | `0FFC270` | **`05FC270`** |

`decode_spi_capture.py` 已增加 `conserviss` 匹配注释。

### 3.4 对本板位流扫描（2026-08-28）

| 模式 | 结果 |
|------|------|
| Conserviss CDCE **整表**连续 BE/LE | **0** |
| Reg0 `683C0350` / 旧 `683C0340` | **0** |
| Reg0/RegA **Hamming≤2**（BE/LE） | **0**（见 `位流SPI常量搜索.md` §5b） |
| ADC 字对 `4180\|5004` 连续 | **0** |
| 散点 `02008083`（`83800002` LE）等 | 个别噪声级命中，**不成簇**；ham≤1 多 Reg 共窗 **0** |

→ 仍支持「非明文 ROM 拷贝」；**不**排除运行时状态机发同等序列（P1.5 仍须上电嗅探）。

## 4. 对算法命题（P2）的影响

| 观察 | 对本板 |
|------|--------|
| 参考 IP = **时域 AXI-Stream 进出** + 可选 DDS 示例 | 形态 **A**（段采/流式时域）先验再加强 |
| 参考工程**无**板内 FFT/DDC 模块；谱分析在 `host/analyze_adc_capture.py` | **不能**排除本板另做；但「FMC150 血统＝板内 FFT」归因 **排除**（§4.1） |

## 5. 数据通路契约（Conserviss · 供 G3 对照，非本板结论）

### 5.1 ADC AXI-Stream（`docs/fmc150_adc_ip.md`）

| 字段 | 含义 |
|------|------|
| `tdata[15:0]` | ADC-A，14-bit **符号扩展**到 16 |
| `tdata[31:16]` | ADC-B，同上；与 A **同一采样时刻** |
| 时钟 | `m_axis_aclk` ≈ **245.76 MHz**（转发钟） |
| 成帧 | **无 TLAST**；连续流；应用层自定帧 |
| 背压 | ADC **不可**反压；FIFO 满则丢样（`tuser[0]` 标记） |

### 5.2 DAC AXI-Stream（硬件口径以 `limitations.md` 为准）

| 项 | 值 |
|----|-----|
| 样率进 DAC IP | **122.88 MHz** 一对 A/B |
| DATACLK | 245.76 DDR |
| 插值 | **2x**（CONFIG1=`0x21`） |
| 字节序 | A 高字节→A 低→B 高→B 低（相对 DATACLK） |
| 面板映射（FMC150） | DAC3283 **A→面板 DAC D**，B→DAC C（**非**本板丝印；本板为 DAC1/DAC2） |

> 注意：`docs/fmc150_dac_ip.md` 仍写「意图 4x / CONFIG1=0x31」——与同仓 **`limitations.md` + `dac_config_pkg` 硬件定案 2x** 冲突；**以 limitations/config_pkg 为准**。

### 5.3 主机侧

- UART 诊断协议（`docs/uart_protocol.md`）：本板是 **FT600+ETH**，协议**不可照搬**，仅作「命令字+参数」形态参考（H7）。  
- `analyze_adc_capture.py`：默认 `fs=245.76e6`，14-bit 有符号码，**主机 FFT/拟合**——支持 H2。

## 6. Conserviss `limitations.md` 再加深（R11 · 2026-08-28）

> 来源：同仓 `docs/limitations.md` + `examples/dds_blockdesign/`；仍**非**本板源码。

### 6.1 带宽与通路形态（对本板 P2.1/P2.2 先验）

| 事实（参考仓） | 对本板含义 |
|----------------|------------|
| 双通道满速：245.76 MS/s × 2 × 16 bit ≈ **7.86 Gbit/s（≈983 MB/s）** | 与 G0「ADC 满速 ~875 MB/s（14-bit 打包口径）」同量级；**GbE ≈118 MB/s、FT600 典型 340–400 MB/s 均远低于满速** → 「连续满速双通道原始上传」**不像**；H1 段采/深缓冲或抽取 二选一（或并存） |
| ADC 样率 : DAC 数据率 = **2:1**（245.76 vs 122.88） | 参考仓写明：**数字直通须抽取**；在钟**计划 B** 成立时，本板「无抽取 ADC→DAC 数字直通」假说应降权（条件句，须 G2 确认钟） |
| 诊断缓冲仅 1024 样/通道；本板 DDR3×2 | 再次拉开：本板更像深缓冲（H1），非浅 BRAM 快照 |

### 6.2 配置归属（P1.5 参考实现）

- Boot 期间 **control IP 独占 SPI**，直至全部 init FSM 结束；主机适配器**不能**抢总线。  
- CDCE **运行时不改表**（固定 `fmc150_cdce_config_pkg`）；恢复靠复位。  
→ 支持「上电嗅探即可定模式」的 G2 策略；本板是否同构仍 ❓。

### 6.3 DAC 联调靶标（G3 预备）

| 手段 | 内容 |
|------|------|
| **iotest** | CONFIG1 `iotest_ena`；CONFIG9–16 图样；FRAME 上升沿标首字；CONFIG8 报失败 bit；模拟输出强制关 |
| **TXENABLE** | 参考仓禁止常量拉高；`dac_output_guard` 要求 init 回读通过 + 钟锁定 + FIFO 未饿死 |
| **DDS 示例打包** | `TDATA[15:0]=A`，`[31:16]=B`，2's；相位步进相对 **122.88 MHz** |
| **面板映射（仅 FMC150）** | DAC3283 A→面板 **DAC D**，B→**DAC C**；**勿**套用到本板 DAC1/DAC2 |

### 6.4 SPI / 分频评分加深

| 工具 | 作用 |
|------|------|
| `decode_spi_capture.py` | `conserviss_dac_pre_sync_hits/ratio` + CDCE 剖面 |
| `decode_cdce_profile.py` | 解 Reg1–8 bits[19:13] Table-8；Conserviss 下 **已识别使能输出均为 ÷2 → 245.76**；Reg2 注释=ADC 钟 |
| `g2_mode_infer.py` | SPI 命中 Conserviss → 自动注「计划 B：C2≈C3≈245.76」先验 |

抓包后若 CDCE ratio 高 → 强支持 Conserviss/FMC150 类 init（仍非本板证明，但是 P1.4 剖面 + 测钟先验）。

## 6.5 ADC 对齐形态对照（R11c · 2026-08-28）

> 来源：同仓 `docs/limitations.md`「Input delay is one shared tap」+ `fmc150_control_ip.md` ADC 仅写 `0x4180`/`0x5004`。仍**非**本板结论。

| 公开形态 | 对齐做法 | 上电 SPI 是否见测试图样 | 对本板 H5 含义 |
|----------|----------|-------------------------|----------------|
| **Conserviss（R11c）** | 全 14 数据 lane **共享 1 个 IDELAYE2**；默认 tap **11**；实测窗口约 taps **0–22**；**无 bitslip**；无 per-lane deskew | **否**（ADC init 仅 DDR-LVDS + 2's） | SPI **无** 0x62/0x75 **不能**证伪「链路未校准」——可能是静态硬扛 |
| Avnet/SDSU（R2/R3） | 手工设 iDelay≈25 | 常配合 ramp | 见测试图样则 H5/手工校准支持 |
| RHINO（R5） | SPI 开测试图样 + 按误码自调 IODELAY2 | **是** | 见 0x62/0x75 往返 → H5 支持 |

**G2 判读纪律**：`H5_test_pattern=false` + Conserviss CDCE/ADC 剖面命中 → 注释「相容静态 IDELAY 形态」；升 P1.2 边沿 ✅ 仍要 G2-5 探随路 CLK / 或 G3 ramp。

**control_ip 安全红线（抓包旁证）**：勿期望运行时把 ADC `0x41` bit7 清零（会切 CMOS，与 LVDS 终端冲突）；Conserviss 适配器明确禁止。

### 6.6 SPI 单向陷阱（R11d · pin_map）

> 来源：Conserviss `docs/pin_map.md`（VC707+FMC150 硬件踩坑记录）。**本板是否有同款电平转换 ❓**，但三芯片 datasheet 本就分立 SDO——纪律通用。

| 事实（FMC150 卡） | G2 动作 |
|------------------|---------|
| `SPI_SDATA` 经 SN74AVC4T245 **固定 FPGA→卡**，**不可双向** | LA **不要**把 MOSI 当 MISO 采；回读必须挂 **独立** CDCE `SPI_MISO` / ADC `SDOUT` / DAC `ALARM_SDO`（或 4-wire SDIO） |
| 误把 SDATA 当双向 → 写成功、读回全 `0xFF` | 若抓包「写像对、读全 FF」→ 先查探点，再谈 EEPROM/故障 |
| DAC `TXENABLE` 单独脚；参考仓约束默认拉低 | 探 CH7 看何时释放；**勿**上电初期强驱高 |

本板探针表已列独立 SDO（`G2_仪器与探针清单.md` CH5/CH6）；本条把「为何必须分立」钉死为 **Conserviss 实测教训**，避免 P1.4/P1.5 误判。

## 6.7 验收双判据（R11e · `host/run_acceptance.py`）

> 来源：Conserviss `host/run_acceptance.py` + `docs/uart_protocol.md`。UART **不可**照搬本板；下列数字可作 **G2 测钟/SPI 身份**先验。

| 判据 | Conserviss 验收 | 本板 G2 用法 |
|------|-----------------|--------------|
| DAC 参考钟窗 | `DAC_CLOCK` 读 `CLK_TO_FPGA`，名义 **245.76 MHz ±1%** | 与 `g2_mode_infer` 族容差 **1%** 一致；计划 B 下 C3/C4 应用同窗 |
| DAC 身份 | `DAC_PROBE` → CONFIG31/`VERSION31` **version[5:0]=0x12** | SPI 回读见 VERSION → checklist `D2_dac_version_read`；infer 可建议 P1.4 **强 🔶** |

| 浅缓冲对照 | UART `ADC_BUFFER`=**1024** 样/通道 | 再证本板 DDR3×2 ≠ 参考浅 BRAM（H1） |

**纪律**：双判据同时命中（钟∈窗 + CONFIG31=0x12）只说明「像 Conserviss/FMC150 类前端配置」；**不能**单独把本板 P1.3/P1.4 升到 ✅（仍须本板探点实测哈希）。

## 6.8 双路 DAC 模拟出核实（R12 · tip `3fab895`）

> 来源：Conserviss `docs/limitations.md`「The DAC data path — verified on both channels」（Update 2026-08-14）+ tip 提交说明。

| 事实（VC707+FMC150） | 对本板 |
|---------------------|--------|
| Ch.A 1 MHz 单音实测干净（194 mVpp）；Ch.B 接 DDS 余弦后**两路面板口均干净正交单音** | 同构前端上 **双 DAC 通路可同时工作** 的公开先例 → 支持本板 **DAC1/DAC2 双路** 照片拓扑（P1.1），**不**升本板 ✅ |

## 6.9 RHINO 计划 C 钟剖面（R5c · 论文 §5.1.1）

> 来源：UCT RHINO 硕士论文公开 PDF §5.1.1（与 R5/R5b 同平台）。**非**本板源码。

| 项 | 内容 |
|----|------|
| VCXO | 491.52 MHz；参考 100 MHz PRI |
| **Fout2 → ADS62P49** | **61.44 MHz**（÷8，LVPECL） |
| **Fout4 → FPGA** | **245.76 MHz**（÷2，LVDS，`CLK_TO_FPGA`） |
| **Fout7 → DAC3283** | **245.76 MHz**（÷2，LVPECL） |
| Reg0 / RegA | 与 Conserviss 同族：`683C0350` / `05FC270A` |
| Reg2 | 论文 Table 5.2 OCR=`83080002` **无法**按 Table-8 解出 ÷8；脚本用合成字 **`83040002`**（bits[19:13]=`0000010`）作 Plan C 靶标 |

**纪律**：计划 C 是 RHINO **示例率**，不是 Conserviss 硬件默认；G2 测得 61.44 **勿当出族**，也**勿**因此假定本板走 RHINO 固件。

## 6.10 RHINO_CALF 公开 HDL：DDC/DUC·NCO（R5d）

> 来源：GitHub `SDRG-UCT/RHINO_CALF` → `fmc150-io/fmc150_if.vhd`（公开 VHDL，**非**本板）。  
> 目的：给计划 C 族补一条**可核验的通路形态先验**——同平台示例固件**显式**含 FPGA DDC/DUC（NCO），便于 G3 设计证伪；**禁止**写成「s2056 必有 NCO」。

| 项 | 内容 | 等级 |
|----|------|------|
| 模块 | 注释与信号：`DDC` / `DUC`、`dds_reset_ddc` / `dds_reset_duc` | ✅（对该开源仓） |
| NCO 字 | `FREQ_DEFAULT = x"3200000"`（28-bit）；注释：`Fc/Fs*2^28`，**Fs = 61.44 MHz**，备选 `x"CE00000"`（−12 MHz） | ✅ |
| 与计划 C | NCO 公式显式用 **61.44** → 与 R5c 样钟同族 | 🔶 先验 |
| IDELAY 初值 | `CLK/CHA/CHB_IDELAY = 0`（≠ Conserviss 默认 tap 11） | 🔶 对照 |
| ADC 校准 SPI | 写 addr `0x62`/`0x75` 切 ramp↔normal（`idata=4/0`） | 🔶 G2/G3 靶标旁支 |
| 对本板位流 | 搜 `0x03200000` BE×35 / LE×19（**低辨识度噪声**）；`0x0CE00000` **0** — 见 `位流SPI常量搜索.md` §5e | ✅ 阴性/噪声 |
| **归因纪律** | RHINO_CALF **有** DDC/DUC ≠ s2056 **有**；仅升「G3 应做 H-DDC 证伪」优先级，**不**升 P2.3 | Must-2 行已补 |

**下一步**：G2 若确认计划 C，G3-3 优先做「改 Fin 看上传是否出现固定本振差频」以证伪/支持 H-DDC。
