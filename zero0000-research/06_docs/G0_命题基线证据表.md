## 1. P1 — ADC/DAC「如何实现」

### P1.1 模拟前端拓扑 —— 当前 **🔶**

| 项 | 内容 |
|----|------|
| 命题标准 | SMA→耦合→ADS62P49 / DAC3283→SMA 与照片一致；通道对应 SIG1/2、DAC1/2 |
| 现有证据 | [BOM] §一：U1=ADS62P49 顶标 ✅，旁证「SIG1/SIG2 SMA → T5–T8 四只射频变压器 → U1」照片链路；U3=DAC3283 ✅ 且「输出链路通向 DAC1/DAC2 SMA」；§四：SMA×6 丝印 `DAC2/DAC1/CLK_IN/TRIG/SIG2/SIG1` ✅。[信号链] §2/§3：AC 耦合与端口映射按 FMC150 同构给出（🔶），§3 末明确「SMA→芯片逐点确认」为 ❓ 待核实。[L3] §1：SMA 具体分配整体标 🔶/❓。[G1追加] 图27 复核：ADC 侧 T5–T8 变压器簇、DAC 侧 L2–L9 重建滤波+缓冲再出 SMA（🔶，截止频率仍 ❓） |
| 升到 ✅ 缺什么 | 万用表/示波器从 SMA 中心针到芯片引脚的**逐点连通性实测**（[信号链] §4 准备项），确定 SIG1/SIG2 与 ADC 通道 A/B、DAC1/DAC2 与 IOUTA/IOUTB 的一一对应，以及耦合方式（AC 变压器 vs 直流）终验 → 需板，G2 被动测即可 |

### P1.2 数字接口（DDR LVDS）—— 当前 **🔶**

| 项 | 内容 |
|----|------|
| 命题标准 | ADC→FPGA 为 DDR LVDS；FPGA→DAC 为 8-bit DDR LVDS+FRAME（示波器或 ILA 见到边沿/帧） |
| 现有证据 | [信号链] §1.1/§1.2：ADS62P49 仅有 DDR LVDS / 并行 CMOS 两种输出，CMOS 上限 210 MSPS，245.76 MSPS 时钟计划下 LVDS 是唯一现实选择（✅ datasheet 排除法）；DAC3283 的 D[7:0]P/N+DATACLK+FRAME 8 对 LVDS 是**器件唯一接口**（✅ 器件级）。[L3] §1 框图说明表：两条链路均标 🔶 |
| 升到 ✅ 缺什么 | 命题标准括号内的实证本身——示波器探 LVDS 对见到 DDR 边沿 / FRAME 帧，或 FPGA ILA 抓解串数据（[信号链] §4.2/§4.3；研究计划 G2-5）→ 需板与差分探头/LA，G2 |

### P1.3 采样/更新时钟实测 —— 当前 **❓**（候选值假说已达 🔶）

| 项 | 内容 |
|----|------|
| 命题标准 | **测得** ADC 样钟、DAC DACCLK 实际频率（候选 245.76 / 491.52 MHz 族） |
| 现有证据 | [BOM]/[时钟树]：X1=491.52 MHz VCXO 丝印 `HCI AE 491520` 紧贴 CDCE72010（🔶）；[信号链] §2 要点 1：/1、/2 分频能力 ✅（datasheet），但「DAC 491.52 / ADC 245.76」的频率计划仅为 FMC150 惯例（🔶）；[SPI靶标] §5.3：SCAA090 出厂 EEPROM 默认恰按 491.52 MHz VCXO 预设（旁证）；**另** TI TSW4200-ADC 官方默认亦为 491.52 VCXO ÷2 → 245.76（`G1_TSW4200与上位机检索.md` R8）→ 频率计划先验再加强，**等级仍 ❓**（命题标准=实测） |
| 升到 🔶→✅ 缺什么 | 命题标准就是实测，静态资料**原理上无法达成**：需示波器探 CDCE72010 输出 / ADC CLKP / DAC DACCLK（研究计划 G2-2；[信号链] §4.1 步骤已写好）→ 必须 G2 |

### P1.4 器件工作模式（SPI 寄存器）—— 当前 **❓**

| 项 | 内容 |
|----|------|
| 命题标准 | SPI 抓到的寄存器：ADC 0x41 DDR/增益；DAC 插值倍数、粗混频开关；CDCE 分频与 LOCK |
| 现有证据 | [SPI靶标] 全表：三片器件的帧格式、关键寄存器地址（ADC 0x41/0x20…、DAC CONFIG0–1/0x1F、CDCE Reg0–RegC）与 FMC150 已验证配置值均已备好为**比对靶标**；但其 §1.2/§7 免责声明明确：对本板一律 ❓，「没有任何证据表明该位流内实现了上述 SPI 主控或寄存器序列」，位流中也搜不到寄存器写表（综合位流不保留） |
| 升到 ❓→✅ 缺什么 | 逻辑分析仪挂 SPI（SCLK/MOSI/CSn×3）抓上电初始化序列，按 [SPI靶标] §6 勾选 G1–G4 / A / D / C 判定项（研究计划 G2-3/G2-4）→ 必须 G2 |

### P1.5 配置归属（位流内逻辑自动 SPI vs 主机下发）—— 当前 **❓**

| 项 | 内容 |
|----|------|
| 命题标准 | 判定上电后前端配置来自 Flash 位流内逻辑自动 SPI，还是主机事后下发 |
| 现有证据 | [位流] §1.1：FPGA **自身**为 Master-SPI 自举（✅，BSPI_READ 命令实证）——但这只回答 FPGA 配置来源，不回答前端三片的 SPI 归属；[SPI靶标] §5.1：CDCE72010 有片内 EEPROM 自举路径，「即使 FPGA 不发 SPI，时钟输出也可能已经在跑」→ 存在**三种**候选（位流逻辑 / 主机 / EEPROM），静态无法裁决；[L3] §3 控制链路表已把该项登记为 ❓。[SPI常量]：镜像内 FMC150 公开 CDCE Reg0/A/B 等高辨识度 full32 **零命中、无成簇**→ 削弱「照抄 E2E 明文 ROM 写表」细假说，但**不裁决**三种候选（等级仍 ❓） |
| 升到 ❓→✅ 缺什么 | 上电时序嗅探：主机不接入、仅上电，看 SPI 有无自动写序列；再接主机看有无二次下发；无写序列但时钟在跑则用 CDCE 0xE 读命令回读比对 EEPROM（[SPI靶标] §5.4）→ 必须 G2 |

## 2. P2 — 「用了什么算法」（FPGA 数据通路）

### P2.1 有无深缓冲 —— 当前 **🔶**

| 项 | 内容 |
|----|------|
| 命题标准 | DDR3 读写活动与段采/连续流行为可区分 |
| 现有证据 | [BOM]：DDR3 IS43TR16128D ×2 = 512 MB 在板 ✅；[L3] §2 带宽预算：USB3（FT600Q 实测典型 340–400 MB/s）与 GbE（≈118 MB/s）均低于 ADC 满速产出（≈875 MB/s）→「DDR3 大概率是采集缓冲/段采」为量化推论 🔶；[位流] §4.2：MIG/DDR3 控制器「大概率存在」🔶，53% 高逻辑占用相容 |
| 升到 ✅ 缺什么 | 实测区分段采 vs 连续流（短时连续采 vs 触发采观察 DDR/吞吐，研究计划 G3-5），或命令协议中出现「深度/预触发点」参数（[L3] §2 验证方法）→ 需 G3 |

### P2.2 有无抽取/重采样 —— 当前 **❓**

| 项 | 内容 |
|----|------|
| 命题标准 | 主机侧样率 ≪ ADC 时钟，或寄存器/命令暴露抽取倍数 |
| 现有证据 | 无正面证据。[L3] §2 仅推出「必须缓冲**或**抽取」的二选一，未裁决；[位流] §4.1 字符串阴性对该维度不可用；[算法对照] §3 已把「上位机头文件中的采样格式/抽取符号」列为 G1 待填项 |
| 升级路径 | ❓→🔶：G1 拿到上位机/DLL/头文件即可（**不需板**，但需外部资料）；🔶→✅：G3-2/G3-3 实测主机侧样率与注入频率关系 → G3 |

### P2.3 有无数字下变频/NCO/FIR —— 当前 **❓**

| 项 | 内容 |
|----|------|
| 命题标准 | 频谱平移、镜像抑制、滤波响应与激励频率的关系可复现 |
| 现有证据 | 无正面证据。DAC3283 片内粗混频（Fs/2、±Fs/4）与 2x/4x 插值 FIR 是**器件能力**（[信号链] §1.2 ✅），不构成本板 FPGA 内 DDC/NCO 的证据；[算法对照] §2 明确「可借作假说、不可当结论」；[位流] 无网表符号，不可检索 NCO/FIR 字样（§4.1 阴性维度） |
| 升级路径 | ❓→🔶：G1 资料出现 NCO/DDC/FIR 符号或寄存器名；🔶→✅：G3-3 改注入频率/幅度看上传数据、G4 判别矩阵 H-DDC/H-FIR 行 → G3/G4 |

### P2.4 有无 FFT/检波等 —— 当前 **❓**

| 项 | 内容 |
|----|------|
| 命题标准 | 上传数据已是谱/功率而非时域 IQ/实采样 |
| 现有证据 | 无正面证据。弱阴性线索：[位流] §3.2 BRAM 内容区近乎全零 → 已初始化 BRAM ROM 极少，BRAM 更像清零即用的缓冲/FIFO（🔶，但该文未据此对 FFT 下结论，本表也不越界）；判定必须看上传数据本身 |
| 升级路径 | ❓→🔶/✅：G3-2 打通收数后用 `scripts/l5_fft_check.py` 判上传的是时域还是谱（`05_tests/L5_功能实测方案.md`）；G4 矩阵 H-板内FFT 行（2^n 定长谱 vs 可变长时域流）→ G3/G4 |

### P2.5 有无软核调度 —— 当前 **🔶**（方向：倾向无 BRAM 驻留软核）

| 项 | 内容 |
|----|------|
| 命题标准 | ILA/总线看到 CPU 总线周期，或仅纯流水线 |
| 现有证据 | 这是 P2 中唯一被静态证据实质推进的一条。[位流] §3.2/§4.2：BRAM 内容区近乎全零 → PicoBlaze 与「BRAM 驻留程序的 MicroBlaze」可较有把握排除（🔶）；SPI/DDR3 引导的小 MicroBlaze 不能排除（❓）；[网络常量] 结论：无硬编码 IP/MAC/端口，「非带网络栈的 CPU 固件镜像」✅ 同向支撑；综合判读=「中高占用（53% 非零帧）的定制数据通路设计」🔶 |
| 升到 ✅ 缺什么 | 两条任一：① Vivado 帧地址表定死 blk=1 边界，把 BRAM 用量 🔶→✅（[位流] §6，**需工具不需板**，但仍只能加强排除、无法证实/证伪小核）；② JTAG readback BRAM 观察运行期是否装载程序 + ILA/命令延迟抖动观测（[位流] §6；G4 矩阵 H-软核主控行）→ 终判必须 G2+（JTAG）/G4 |

### P2.6 主机协议语义 —— 当前 **❓**

| 项 | 内容 |
|----|------|
| 命题标准 | 命令→采/放/触发的状态机可画出 |
| 现有证据 | 无正面证据。[位流] §4.1 + [网络常量]：位流内无协议明文、无 IP/MAC/端口常量（✅ 阴性，且「阴性≠无该功能」）；[L3] §3 命令协议格式登记 ❓；已备好的只是**手段**而非证据：`scripts/ft600_scaffold.py`、`scripts/udp_probe.py`、`04_comms/L4_通信测试方案.md` 判定线 |
| 升级路径 | ❓→🔶：G1-d 拿到别人抓的包样例做离线解析（**不需板**，需外部资料）；🔶→✅：G3-1 打通 USB/ETH 实抓命令与数据帧 → G3 |
