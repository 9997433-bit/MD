## 0. 三条铁律(先读这个)

1. **先备份,后实验。** 任何写 Flash、拨开关、改配置的动作之前,必须先完成固件备份(见 §3)。
2. **先确认,后推断。** 本课题所有结论都带证据等级:✅ 确认 / 🔶 推断 / ❓ 待证。写文档、做汇报时不允许省略等级标注。
3. **不确定就停。** 尤其是供电——本板输入电压规格至今 ❓ 未知,盲目上电可能直接损坏硬件。

## 1. 你在研究什么

一块基于 **Xilinx Kintex-7(XC7K160T ✅)** 的高速信号板,板上有:

- 双通道 14bit 250MSPS ADC(ADS62P49)+ 双通道 16bit DAC(DAC3283)
- CDCE72010 时钟分配、DDR3 ×2 缓冲、S25FL128S SPI 配置 Flash
- 主机接口:FT600Q USB3.0 FIFO 桥 + RTL8211FI 千兆以太网

原始输入只有两样:一份固件 `20230825_s2056.mcs` 和七张 PCB 照片(都在 `assets/` 下)。全部分析从这两样东西出发,这就是为什么大量结论还停留在 🔶/❓。

应用域尚未定论,现有三种假设(数据采集卡 / SDR 收发平台 / 信号链测试仪),判别实验矩阵见 `03_architecture/L3_系统架构.md` §4。

## 3. 上电前检查清单

**上电不是默认动作,是一次实验。** 每次上电前逐项打钩:

- [ ] **输入电压已确认。** 电源输入规格目前 ❓ 未知(疑 5–12 V)。在完成 `01_hardware/电源树.md` 待证实验 1(测通断 + 查 buck 耐压)之前,**禁止随意接电源**。
- [ ] 供电电流限制已设置(实验室直流源限流,首次建议 ≤1 A 起步观察)。
- [ ] 防静电措施到位:手环接地,拿板只碰边缘。
- [ ] JTAG 线缆已接好(**断电状态下接线**,再上电)——JTAG 是最底层的保底通道。
- [ ] **不要动 SW5 拨码开关**:功能 ❓ 未知,可能改变启动模式;固件备份完成前禁止拨动。
- [ ] 上电后第一件事:观察 DONE 指示灯,并按 SOP §2 做**只读**的 Flash 回读备份。备份完成前,不做任何写操作。
- [ ] 记录:日期、操作人、电源电压/电流读数、现象。

## 3.1 固件备份 SOP 入口

完整流程在 **`02_firmware/SOP_kintex7_spi_flash_backup_program_rollback.md`**,这里只给你必须记住的骨架:

1. **备份(§2)**:Vivado Hardware Manager → Add Configuration Memory Device(选对 S25FL128S 尾缀!)→ Readback 全片 → **读两次比对 SHA256** → 存两处。
2. **烧录(§3)**:核对待烧文件哈希(`20230825_s2056.mcs` 的 SHA256 = `dc91db8e…67507c0`)→ Erase + Program + **Verify 必勾** → 过程中绝不断电拔线。
3. **试跑(§4)**:JTAG 直接烧 `.bit` 是**易失**的,断电即失——这是零风险验证手段,但需要 `.bit` 文件(目前只有 mcs)。
4. **救砖(§5)**:只要 JTAG 还能识别到 `xc7k…`,就没有真砖。上电即死时,按住 PROG 键(拉低 PROGRAM_B)阻止加载,再连 JTAG 重写。

## 5. 常见误区

1. **"mcs 没有明文字符串,所以固件加密了。"** 错。已确认**未加密**(CTL0 DEC=0,熵 ≈1.14 bit/byte ✅);无明文只是 MCS 剥离 `.bit` 头后的正常现象。
2. **"JTAG 烧完 bit 就算固化了。"** 错。JTAG 配置是易失的,断电即丢;固化必须走 SOP §3 写 Flash。反过来这也是优点:JTAG 试跑永远不会"越烧越坏"。
3. **"DONE 灯不亮 = 板子砖了。"** 只要 JTAG 能识别到 FPGA 就一定可救(Kintex-7 的 JTAG 独立于配置模式引脚),按 SOP §5 走。
4. **"USB3 能扛住 ADC 满速流。"** 不能。ADC 双通道满速产出 ≈875 MB/s,超过 FT600Q(约 340–400 MB/s)和千兆网(约 118 MB/s);因此 DDR3 大概率是段采集缓冲 🔶,别按"连续流"设计实验。
5. **"照片上看着像,就当确认了。"** 照片丝印只能给 🔶,升 ✅ 必须实测或文档确证。写文档漏标等级 = 返工。
6. **"K160T 的 IDCODE 是 0x03631093。"** 旧笔记有误,正确值为 **`0x0364C093` ✅**(已在 `02_firmware/固件结构分析.md` 更正)。引用旧资料时注意甄别。
7. **"本板 = USB-4431 / destly 同款。"** 立项时已明确不做此等同(见 `00_meta/立项说明.md` 范围表),只做关联对照。
8. **"Flash 型号随便选一个就行。"** S25FL128S 尾缀 …0(256KB 扇区)与 …1(64KB 扇区)在 Vivado 中是不同条目,选错是烧录失败最常见的原因,先看芯片丝印。
