## 一、技术风险

### 1. 变砖(固件不可恢复)

**风险来源**

- SPI Flash 被误擦除/误写入(iMPACT / Vivado HW Manager 误操作、写错偏移)。
- 烧录过程中断电、JTAG 线松动导致 Flash 内容半写状态。
- 写入了未验证的 bit/mcs(引脚约束错误可能造成 IO 冲突,见"过压"节)。

**控制措施**

| 措施 | 要求 |
|------|------|
| 全片备份 | 首次接触实物,**任何写操作前**必须完整读出 SPI Flash 并校验哈希,双份异地保存(本仓 `assets/firmware/` + 本地) |
| 回滚验证 | 备份后先做一次"擦除→回写→回读比对"演练,确认回滚通路可用,再进行任何修改 |
| 供电保障 | 烧录期间不使用可疑电源;避免烧录中拔插任何接口 |
| 原始镜像只读 | `20230825_s2056.mcs` 原件永不覆盖,实验固件另起文件名 |

**残余风险**:若 Flash 芯片本身物理损坏,可拆焊后用编程器离线烧录同型号备件;JTAG 直接配置 FPGA 不依赖 Flash,可作为最终诊断通道。

### 2. 过压 / 电源接错

**风险来源**

- **输入电压规格未知**(仅推断 5–12 V,见电源树 ❓ 项)。接高了直接击穿第一级 buck 或防反接件。入口钽电容(220 µF)耐压仅 16 V,可视为输入电压硬上限。
- 电源正负极接反(红黑线为自接线,不可默认极性正确)。
- 自制固件 IO 约束错误(电平标准/方向配错)造成 bank 过应力。

**控制措施**

1. **上电前提**:先完成电源树"待证实验 1"(确认输入耐压范围),未确认前禁止直接接可调电源高压端。
2. 首次上电使用**可限流的实验室电源**,从推断下限(5 V)起步,限流 0.5 A,观察电流曲线与发热,逐步放开。
3. 上电前万用表确认输入插座极性、对地阻抗(排除短路)。
4. 自制固件先在空板约束仿真/DRC 通过,首版仅点灯级逻辑,不驱动 ADC/DAC/DDR 接口。

### 3. ESD(静电损伤)

- FPGA、ADC(ADS62P49)、DAC(DAC3283)、时钟芯片(CDCE72010)均为 ESD 敏感器件;SMA 中心针直连模拟前端,是最脆弱的注入点。
- 操作要求:防静电手环+防静电垫;不用手触碰 SMA 中心针与板上裸露引脚;板卡运输、存放使用防静电袋;冬季干燥环境先触摸接地金属再拿板。
- 示波器探头、信号源电缆接入前先共地。

### 4. SMA 口灌电(信号口过驱)

**风险来源**

- ADC 输入(SIG1/SIG2)满量程通常仅 2 Vpp 量级且可能直流耦合,信号源直接输出大幅度/带直流偏置的信号会损坏 ADC 前端。
- DAC 输出口(DAC1/DAC2)被误当输入口接信号源 → 对输出级灌电。
- CLK_IN / TRIG 电平标准未证(见接口定义表 ❓),盲目接 5 V TTL 触发可能过压。

**控制措施**

1. 接任何信号前,核对接口定义表,**分清输入/输出口**;DAC 口只允许接高阻测量设备。
2. ADC 输入首次测试:信号源从 -20 dBm(约 63 mVpp)起步,确认无直流偏置(必要时串 DC-block),逐步加大。
3. CLK_IN / TRIG 未确认电平前,幅度不超过 1.8 V,先用示波器高阻探头确认板侧空闲电平。
4. 所有 SMA 转接件拧紧再上信号,避免热插拔打火。

### 5. USB / 外部电源互灌(反灌电)

**风险来源**

- 板卡同时接 USB3(主机 VBUS 5 V)与外部 DC 输入。若板上无理想二极管/隔离设计(未证 ❓),两路电源可能经 3.3 V 轨互灌:主机 USB 口反向带载,或外部电源经 VBUS 灌回主机。
- 板卡断电但 USB 仍插着:主机 VBUS 可能经 FT600Q 的 IO 保护二极管给整板"寄生供电",造成芯片 IO 先于电源轨上电(latch-up 风险)。

**控制措施**

1. **上下电顺序**:先接外部电源并上电,后插 USB;下电反序(先拔 USB,后关电源)。
2. 首次联机使用**带隔离/限流的 USB HUB** 或牺牲品主机口,不直接接主力工作机。
3. 万用表确认 VBUS 与板上 3.3 V/5 V 轨的通断关系,补充进电源树后再放宽操作要求。
4. 以太网口为磁隔离,风险较低,但也遵循"板卡先上电"的顺序。

## 二、合规与法律边界

### 6. IP / 逆向工程边界

本课题定位为**互操作性与技术学习目的的分析研究**,自我约束如下:

| 允许 | 不做 |
|------|------|
| 读取、备份自有板卡的 Flash 内容用于研究与恢复 | 破解、绕过任何加密/授权机制(本固件已确认未加密,不涉及) |
| 分析位流头部、结构、IDCODE 等元数据 | 对位流做 netlist 级反编译并复制其设计 |
| 观测总线、协议、引脚映射,撰写互操作文档 | 将他人固件/设计要素用于商业竞品 |
| 自行编写全新固件在同硬件上运行 | 分发、售卖原厂固件或其衍生副本 |

- 位流格式分析仅到公开文档层面(Xilinx UG470 等官方资料);不使用、不发布位流逆向为网表的成果。
- 若后续发现固件内含第三方 IP 核(如 Xilinx LogiCORE),其许可条款随核而定,分析结论只描述"存在什么",不摘录其实现。

### 7. 公开仓库(GitHub)合规

本研究仓库对外公开,提交内容执行以下清单:

1. **不上传原厂固件二进制**:`assets/firmware/*.mcs` 若已入库,应确认原上游(Montyzhang/zero0000)本身即公开发布该文件,且本仓仅作研究镜像并注明来源;否则改为记录哈希 + 外链,不再库内存副本。
2. **不上传可直接复刻的成套设计数据**:不发布任何据此绘制的完整原理图/PCB 复刻文件;硬件文档止步于"证据分级的观测记录"。
3. **来源标注**:所有照片、固件、外部资料在文档中注明出处与获取日期(现行 README/版本矩阵已执行)。
4. **不含敏感信息**:提交前检查无个人信息、内部途径获取的非公开资料、任何形式的密钥/凭据。
5. **芯片 datasheet 不入库**:仅引用型号与公开链接,不上传 TI/Xilinx 等厂商 PDF 原件(多数许可禁止再分发)。
6. 若原作者或权利方提出异议,**优先下架争议内容**,以哈希+描述替代。

### 8. destly 固件版权注意

- `destly`(TopUsb4431,Spartan-3 XC3S200 USB 下载器固件)与 zero0000 为**同作者上传的关联仓库**,但"工具↔目标"关系仅为推断(见版本矩阵,非作者确认)。
- 该固件是**第三方成品二进制**,版权归其原始开发者(可能并非上传者本人——USB-4431 类下载器固件常源自更早的商业/社区工具链)。因此:
  1. **不将 destly 固件二进制复制进本仓库**;需要引用时只记录文件名、哈希与上游链接。
  2. 对其分析仅限识别用途(器件型号、功能定位),不做内容级逆向与再发布。
  3. 文档中涉及 destly 的结论一律标注推断等级,避免以确定性口吻描述其来源与授权状态。
- **严禁混烧**:destly 固件(`usb.cfg`,目标器件 XC3S200)与本板固件(目标 XC7K160T)器件不同,任何情况下不得写入本板 Flash。
- 若实验需要该下载器配套软件,优先寻找官方/公开发行渠道,不使用来路不明的破解版工具。
